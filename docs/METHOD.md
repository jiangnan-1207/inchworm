# Inchworm 实现与实验口径

本实现参考手稿方法部分，尚不能宣称精确复现论文：原文部分超参数未完整给出，所提到的补充细节也未提供。本仓库公开的是工程实现和评测流程，不包含未发表论文。

## 控制器

1. 先生成并确认 warmup 前缀。之后保留已确认前缀和一个增长的待确认窗口。
2. 每个图像 token 的预测熵来自 CFG 与 temperature 后实际用于采样的概率。BF16 softmax 概率转成 FP32 重新归一化再计算熵。
3. 熵变化量等于当前预测熵减去最近 r 个位置的平均预测熵。确认前缀中的变化量截断到非负后，计算分位数阈值；零值保留在分位数计算中。
4. 窗口均值与整个已确认前缀的熵均值比较。到达最大窗口前，均值条件与变化量条件同时成立才触发；到达最大窗口时，任一成立即触发。否则在最大窗口或图像末尾确认。
5. 选窗口内熵最高的 M 个位置，每个位置各自分出 k 个非原 token 的高概率替代分支；不是 M 个位置的笛卡尔积。复用该位置以前的只读 KV cache，重新采样分支后缀。
6. 按窗口平均预测熵选前 N 个，再用平均熵和一步 lookahead 熵的加权和选优，接着继续生成。接受修订后同步更新熵历史。

实现约定：warmup=16；历史不足 r 时使用已有历史；分位数线性插值；分支强制 token 的熵仍是该位置的预测分布熵，不以 token surprisal 替代；图像末尾没有 f+1 图像 token，末窗仅按均值选优。候选选择不把原窗口作为额外候选。

## 默认设置

| 配置 | 数值 |
| --- | --- |
| 最大窗口 L | 12 |
| 历史长度 r | 16 |
| 熵变化分位数 | 0.9 |
| 候选位置 M | 4 |
| 每位置替代数 k | 2 |
| 二阶段候选数 N | 2 |
| 平均熵权重 | 0.5 |
| warmup | 16 |
| 完整实验回溯次数上限 | None，无上限 |

旧单图 smoke 曾限制 2 次回溯；完整集合生成程序不使用这个限制。正式实验仍须在汇报中披露上述工程参数。

## 三组可比性的边界

Janus 两组均为 384×384、576 个图像 token、BF16、temperature=1、CFG=5；baseline 每提示词四图张量批次，Inchworm 逐图生成。种子为 `42 + 4*原提示词编号 + 样本编号`。相同种子不保证不同批次形状、GPU 或软件环境中得到同一图像。

Janus baseline 记录的是每张图片分摊的批次时间，Inchworm 记录逐图时间，不能直接把这两个数当作单样本延迟加速比。若比较效率，应统一批次、硬件、计时范围，并报告吞吐和总 GPU 时间。

LlamaGen 使用 `t2i_XL_stage2_512.pt`，512×512，1024 tokens，CFG=7.5，top_k=1000，top_p=1，temperature=1。它与 Janus 的分辨率和模型规模不同；这里是独立模型的完整集合参考结果，不是控制变量消融。

GenEval 官方提示集 SHA256：`5c48e0813e812e3c373fa5c8ed07a8f0a483be30272b4427b0559c8048e67c13`。按六任务分别统计每张图片的成功率，然后六任务等权平均。四样本不是 best-of-4，也不择优。

## 验证状态

已在此前环境通过核心控制器单元测试、CPU cache/adapter 检查、Janus 原生单图生成和有上限的 Inchworm 单图回溯。LlamaGen 与 GenEval 的旧服务器依赖安装及 CPU 导入/算子检查通过。

新仓库的普通服务器入口、独立安装流程和完整三组 GPU 评测仍需真实运行；单元测试、语法检查和作业提交成功均不能代替完整评分。此仓库不预填任何 benchmark 分数。
